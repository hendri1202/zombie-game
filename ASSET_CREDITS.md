### Where the files came from

Everything ships in the **official glTF 2.0** build published on the pack's own
Google Drive folder, as `agents.md` requires for runtime assets.

- Source: the pack's Drive folder `1mWP6sCHun7OUMHQeDNZLrXTteXlzWg_t`, subfolders
  `Characters/glTF` (`1wtzW_rZvTQ0yiYb6-4P0zwohF6KwCQ6H`),
  `Environment/glTF` (`1GBJC9SeyXAYwhGhqaolbDgkgnzaMUMBc`),
  `Vehicles/glTF` (`1gU4EDvCbI5DCXBUskqYRzmps5Du3KUvF`) and
  `Weapons/glTF` (`1QuDXe9dfk-kkrzLzUVd8GZgoWTT50Owc`).
- Downloaded: 2026-10-15, 42 files, ~20 MB, each verified byte-for-byte against the
  size reported by the Drive listing (`tools/gdrive_list.py`).
- Every file is self-contained: buffers and PNG textures are embedded as base64,
  so there are no sidecar `.bin`/`.png` files to keep in sync.
- Generator string inside the files: `Khronos glTF Blender I/O v1.7.33`.

An earlier revision of this project shipped an **FBX** mirror of the same CC0 pack,
because the Drive download initially failed with "Quota exceeded". That exception is
resolved: no FBX file is shipped, no FBX is loaded at runtime, the loader rejects
non-glTF paths, and `tests/asset-format-policy.test.ts` fails the build if an FBX
path reappears in source or in `public/`. The mirror URL and its caveats are
therefore no longer part of the shipped asset chain.

### Modifications

- The character models are **not** modified on disk. At runtime each variant is
  scaled to its configured height and, for Runner and Brute, the cloned materials
  are tinted so the variants stay visually distinguishable.
- Survivors are normalised to their configured height with the same shared helper
  the zombies use, and their materials are sharpened at load (colour textures
  marked sRGB, anisotropic filtering set to the renderer's maximum). Neither step
  rewrites the file on disk.
- **No shared texture atlas any more.** The FBX build referenced `Zombie_Atlas.png`
  by bare filename from every folder and needed a URL rewrite in `AssetManager` to
  find it. Each glTF file embeds its own textures, so that rewrite and the PNG were
  both removed.
- Files that no feature uses were **deleted** from `public/` rather than shipped
  (the pack's `Knife`, `Axe`, `Shotgun`, `SMG`, `WoodenBat_*`, `Wheel`).

### Not used from the pack

The two dogs (`Characters_GermanShepherd`, `Characters_Pug`) and the `Blood_*`
decals were never copied into the repository. `Zombie_Arm` is also unused: it is a
further zombie variant on the same armature, not a first-person arm rig, so it
would have added 3.4 MB of duplicate enemy art.

## Weapons pack — not used

The PRD lists the Quaternius *Ultimate Guns Pack* as a weapon candidate. Its page
states CC0 but lists **only FBX/OBJ/Blend** (no glTF), and the same kit already
contains a `Pistol` and a `Rifle`, so no second pack was downloaded. No gun mesh
in this project comes from that pack.

## Sketchfab / Mixamo — not used

No asset was taken from Sketchfab or Mixamo. Nothing in the project requires an
account or a per-model licence review.

## Assets generated by the project

None of the following is a downloaded file; all are produced at runtime by
`src/utils/textures.ts`, `src/level/CityLevel.ts`, `src/systems/PickupManager.ts`
and `src/systems/AudioManager.ts`:

- road, sidewalk, dirt and building-facade textures (canvas drawing, original);
- city layout, buildings, perimeter walls, street markings;
- pickup meshes (medkit, ammo box, weapon marker) and their emissive rings;
- muzzle flash, hitmarker, damage vignette, crosshair;
- every sound effect (synthesised with the Web Audio API).

No `eval`, no runtime download of third-party assets, no API keys: the game runs
entirely from local files.
